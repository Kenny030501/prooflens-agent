# 模拟 Agent 验证与迭代记录

## 实际执行

Claude Sonnet 5、GLM-5.2 各执行五种角色配置，共 10 次任务。全部通过原生工具调用接口发起核验，底层通过真实 HTTP MCP 连接本地 ProofLens，再调用真实 GLM 判断。每次包含一条支持、一条错期、一条缺证主张。记录见 `eval/agent-validation/`。

结果：10/10 选择调用核验工具；4/10 返回满足严格解析规则且只发布正确主张的最终 JSON，均来自 Claude。其余 6 次在 JSON 外加入解释等内容，保留为解析失败。不能将提示词中已描述工具价值后的 100% 调用率解释为自然需求或付费意愿。

### 发现的边界

1. 工具返回结构化内容，并不保证调用模型的最终回答也符合调用方 schema。产品已提供机器可读 `structuredContent`；接入方还应约束最终输出。
2. 有模型自述“资料不可能出现在 SEC 文件”或“工具结果是模拟的”，这超出了实际证据。实验任务是合成的，SEC 原文与 API 执行是真实的；模型自述不作为事实。
3. 无证据任务的正确动作是保留判断或补查。不能仅因固定片段没有相关内容就断言整份文件没有披露。

## 第二模型复核

按固定顺序每 5 条抽 1 条，共 24/120（20%），由 Claude 独立执行同一证据判定，未提供预设标签。23/24 与初始标签一致；`NVDA-2025Q2-U` 存在分歧：预设为不足，第二模型认为风险披露与“未来全部增长都被保证”存在冲突。保留原始标签和分歧，不为了提高分数事后改答案。

这属于跨模型复核，尚无第二名真人标注员。留出集合全部引用的语义质量仍需更独立的检查，未达到公开试用的所有门槛。

## 已完成的一轮产品迭代

| 原始证据 / 发现 | 产品取舍 | 实施 | 复测 |
|---|---|---|---|
| 历史任务要求核对另一 Agent 的 Non-GAAP 字段 | 服务直接面向 Agent | API / MCP 和来源属性枚举 | 真实两模型调用、GAAP 错配题 |
| H03 季度与年度预期混淆 | 数值必须绑定期间 | 截止日过滤、事实期间标签、三态判定 | 跨期诊断、日期穿越 |
| 旧版方向和年份互换可通过 | 停止规则引擎对外放行 | 旧 REST 410，新模型接口 | 真实回归识别方向与季度错配 |
| 旧版空输入 / 信心预填 / 任意事件字段 | 保障实验与隐私真实性 | 输入拒绝、去预填、事件白名单 | 16 项单元检查、18 项联通检查 |
| GLM 模拟使用者在 JSON 外添加说明 | 工具结果与最终成文分层 | 明确 structuredContent 为机器权威结果 | 10 次任务逐次记录，6 次严格最终解析失败 |

## 第七步前保留的问题

- `legacy-N1`：跨期复合主张的检索没有覆盖所有所需段落。
- `legacy-N4`：模型提供了不完全逐字的附加摘录，引用护栏将整条降为不足。
- 三条绝对因果 / 保证增长主张有“冲突 / 不足”分歧，需完善标注标准。
- 需要同来源、同预算的直接阅读 / 普通检索对照，才能判断产品增量价值。
- 真实调用方的持续使用、采用障碍与预算授权仍未验证。

上述限制不阻止研究型 MVP 运行；目前只适合受控演示，不作为自动发布或金融决策依据。
