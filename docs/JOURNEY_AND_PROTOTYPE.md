# Agent 任务旅程与原型验证

## 来自真实任务的依据

2026 年 8 月历史投研记录中，已逐句核验 12 条原话，来自 8 个任务、一个使用者。高价值情境包括跨 Agent 验证 Non-GAAP 净利润、季度与全年预期桥接，以及追问实际是否执行了指定工具。完整原始定位在桌面 `用户研究/2026-08历史投研对话/`，不放入可发布源码。

| 阶段 | Agent 任务 | 原来的障碍 | MVP 产品动作 | 观察证据 |
|---|---|---|---|---|
| 准备研究 | 确认公司与时间点 | 混用最新资料与历史判断 | 必填 as_of，按披露日过滤 | 日期穿越测试 |
| 接收草稿 | 将复合表述拆成主张 | 数字相同但期间、口径不同 | 唯一 claim_id、逐项判断 | 覆盖完整性与错配题 |
| 查找原文 | 定位支持证据 | 搜到文件不代表找到支持段落 | TF-IDF、原文片段、来源哈希 | 引用逐字校验 |
| 决定引用 | 保留、修改或补证 | 把工具输出当作绝对正确 | 明确三态及 next_action | 模拟 Agent 的最终选择 |
| 任务结束 | 保存结果供后续使用 | 只有界面、缺少机器接口 | JSON 导出、REST、MCP | 实际调用与事件回执 |

## 原型测试设计

不发偏好问卷。五种模拟配置：赶时间的初级分析师、谨慎审阅者、财务表格整理者、成本敏感研究者、严格接口 Agent。Claude 与 GLM 各运行每种配置，允许选择调用或跳过工具，最多一次来源查询、一次核验。任务中包含一条支持、一条错期、一条无证据主张。

观测：工具选择、参数有效性、证据使用、错误纠正、缺证保留、最终结构化输出、耗时。模型自述“我会使用”不作为需求验证；最终 JSON 无法解析计为失败，原始内容保留。

## 已修复的问题分级

| 问题 | 严重度 | 修复 | 验证 |
|---|---|---|---|
| 空白输入得到 pass | P0 | 去空白校验、1–12 条限制 | 单元与 HTTP 测试 |
| 数字出现即支持，忽略年份 / 增减方向 | P0 | 真实语义判断、证据绑定 | 真实 API 回归 + 120 题 |
| 缺项或模型失败被当作成功 | P0 | 全部 ID 覆盖检查，失败封闭 | 注入模型异常测试 |
| 伪造引用 ID 或摘录 | P0 | 仅允许检索片段 ID 和连续原文摘录 | 自动引用测试 |
| 预填核验后信心影响实验 | P1 | 删除信心预填与总分 | 界面检查 |
| 任意事件元数据可能留存正文 | P1 | 严格事件白名单、拒绝额外字段 | 隐私字段 HTTP 测试 |
| 不清楚模型是否实际执行 | P1 | 真实模型名、用量、来源范围、缓存标记 | 执行回执 |
| 混淆源文件日期和查询日期 | P1 | 同时展示 as_of、source_cutoff、filed_at | 日期测试与 UI |

模型模拟过程发现的额外摩擦、成功率与失败例子写入 `eval/agent-validation/` 和评测报告，不能在运行前预填。
