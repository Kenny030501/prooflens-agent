# ProofLens v0.3 实施说明

日期：2026-09-04。此文是 v0.2 设计与本次 MVP 的实施差异记录，旧文档作为版本历史保留。

## 产品承诺

研究 Agent 提交 1–12 条主张，在固定 SEC 资料范围内获取可追溯的支持关系及下一步动作。网页是调试和审阅入口；直接使用者仍是 Agent。人负责授权、预算和必要的最终复核。

## 已实现的核心流程

公司 / 截止日期 / 明确主张 → 校验输入 → 按披露日和公司过滤 → TF-IDF 检索 → 真实 LLM 结构化判断 → 引用、算术与主张覆盖检查 → 返回证据和动作 → Agent 引用、改写或保留判断。

输出三态：`supported`、`conflicted`、`insufficient`。`evidence_ready` 仅表示本次全部主张获得模型判断的支持，不授权发布、交易，也不表示绝对正确。摘要只保留 supported 主张。

### 本次必要取舍

- 沿用现有 TypeScript / React / Workers / SQLite 栈，实现一次、供三种入口调用；不重建 Streamlit 页面。
- 输入由调用 Agent 拆为显式主张，每行一条。MVP 不增加第二次付费“草稿拆分”调用，避免隐式遗漏；13 条会拒绝。
- 旧 v1 REST 返回 410，停止暴露已知不安全的规则放行逻辑；旧引擎仅保留作历史诊断基线。
- 不生成总体可信度分数，不预填核验后信心；人类 SUS 和信心偏差不作为 Agent 指标。
- 三类来源属性和会计口径均有显式枚举。期间以原文标签保存，无法可靠拆成 ISO 起止日期的字段返回 null；精确财务日历归一化列为后续增强。
- 不自动重试付费调用；格式错误、截断、超时均返回明确失败。调用方可依据错误决定是否用新 ID 重新执行。
- v0.2 的可选 metric / period / basis 输入改为统一主张文本；结构化口径由输出 facts 承载。字段级输入覆盖暂列 P1。
- 本轮只支持固定公共来源，不接受任意 URL，也不将用户历史原文上传给模型。

## 输入 / 输出

REST：`POST /api/v2/evidence-audits`。

必填：`request_id`、`entity`、`as_of`、`claims[{claim_id,text}]`；可选：`language`、`source_ids`。

输出包括全部主张、支持关系、来源、期间口径、推导、缺项、下一动作、摘要、使用量与处理范围。具体 schema 由 `lib/v2/contracts.ts` 维护。

错误：400 JSON、403 跨站请求、413 长度、415 类型、422 字段、409 重复或冲突 ID、429 预算 / 并发重复、502 模型输出不合约、503 配置或持久化不可用、504 上游超时。错误响应不带成功核验结果。

## 来源和隐私

12 份 10-K / 10-Q / 8-K，585 个选定片段；文档哈希、来源 URL、采集日期、披露日期、规范化段落及行号可追溯。行号指本地规范化文本，不冒充 SEC 网页页码。

SQLite 保存来源目录、匿名执行回执、计数和事件。正文不写入数据库或服务端日志；响应仅在进程内最多缓存 10 分钟、最多 30 项。回执持久化后，相同 ID 在缓存丢失时拒绝重做，以免静默重复计费。模型提供商的保留政策仍适用。

预算分配：研究 $5、本机 $3、托管服务 $12，合计 $20；服务每日另有 $2 和 50 次限制。费用是 token 估算，真实账单未知。上游失败保守保留该次预算；不自动充值或释放不明费用。

## 验证范围

离线 120 条是来源约束的合成诊断题；32 条按不同文档留出。两模型扮演五种使用风格，是模拟行为，不代表五名独立真人。第二模型复核与双人标注分别报告。测得的结果见自动生成评测报告。

已形成产品定义和可运行 MVP，不在本阶段宣称市场需求、留存、真人可用性、收入或竞品性能领先。
