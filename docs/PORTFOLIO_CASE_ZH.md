# ProofLens：让研究 Agent 在回答前完成证据审计

> 历史 v0.1 文档：已由 [v0.3 实施说明](PRD_V0.3_IMPLEMENTED.md) 与 [v2 实测报告](EVALUATION_V2_REPORT.md) 取代。下文保留原始设计，不代表当前功能或已验证成果。

## 项目摘要

ProofLens 是一层面向研究 Agent 的可信执行基础设施。Agent 在发布公司研究答案前调用 ProofLens；系统将草稿拆成事实主张，匹配限定的一手资料，返回逐条证据判断和 `允许发布 / 人工复核 / 阻止发布` 门禁。

项目当前交付了可运行控制台、REST API、MCP 服务、WebMCP 渐进接口、十二条 SEC 证据记录、匿名事件模型以及120条评测标注模板。

## 为什么选择这个问题

东方证券实习中的公司研究需要反复核对 SEC 文件、财报口径、产品路线和管理层表述。大模型缩短了信息整理时间，同时会把报告事实、公司指引和分析推断写成同样确定的句子。真正缺少的产品能力不是生成更多内容，而是在发布前强制建立“主张—证据—行动”链条。

## 产品决策

产品采用“80% Agent 接口＋20% 人类审阅控制台”的结构：

- Agent 接口负责稳定的数据契约、证据判断和自动门禁。
- 人类控制台负责展示失败原因、打开原文、修改判断和记录信心变化。
- 系统不输出单一可信度总分，避免把不同类型的错误压缩成虚假精确数字。
- 没有足够证据时返回“未找到证据”，不允许补写来源。

## 个人经历如何转化为产品能力

- AI/TMT 投研：定义一手资料层级和公司研究错误类型。
- 行为与决策科学：把自动化偏误转为审计前后信心校准指标。
- 量化研究：建立固定评测集、基线、失败分类和样本外验证门槛。
- 企业架构与数据建模：设计 Agent、证据、门禁、人工复核和指标之间的数据流。

## 当前证据边界

当前版本是可运行 MVP，不是已经完成用户验证的成熟产品。十二条记录是种子证据，120行文件是待两名人工标注者完成的工作表。尚未开展的访谈、可用性测试和目标指标统一标记为 Pending，不写入简历成果。

## 待验证假设

1. 研究 Agent 的运营者愿意在发布前增加证据门禁。
2. 主张级状态比整篇可信度评分更能帮助用户发现错误。
3. 显示资料期间和口径能够减少对数字相近但定义不同的误用。
4. 人工接管只在高影响主张触发时，不会造成过高流程摩擦。

## 下一轮

先完成5次问题访谈和24条双人独立标注；确认标注规则后扩展至120条，并让8名参与者完成反平衡任务测试。最终只用实测结果替换简历中的指标占位符。
